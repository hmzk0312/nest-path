# MVP計算ルール

この文書は、NestPathの現在のMVPにおける月単位のシミュレーション規則を定義します。

READMEに記載されたMVP要求を補足し、同じ入力から常に同じ計算結果を得るために、月内の処理順序、インフレ、運用損益、売却、現金不足および資産枯渇の判定方法を明確にします。

この文書は要求と計算上の振る舞いを扱います。アーキテクチャ、技術構成および内部データモデルは定義しません。

## 期間と年月の扱い

- シミュレーションは月単位で行います。
- 入力した現在残高は、シミュレーション開始年月の月初残高として扱います。
- 生年月を必須入力とし、年齢は生年月と対象年月から算出します。
- 退職年月は最後の勤務月とします。
- 退職前の定期収入と基本生活費は退職年月まで、退職後の定期収入と基本生活費はその翌月から適用します。
- 定期収入や積立の開始年月と終了年月は、どちらの月も対象期間に含めます。
- シミュレーション終了年齢に達する月を最終月とし、その月の月末残高まで計算します。

## 資産と生活資金口座

MVPでは、資産を次の二つの区分で扱います。

- 現金・預金
- 運用資産

現金・預金として登録した資産のうち、一つを生活資金口座として指定します。生活資金口座として特定される資産は一つだけであり、保有資産全体に含まれていなければなりません。

生活資金口座には、以下の入出金を反映します。

- 定期収入の入金
- 運用資産の実売却額の入金
- 基本生活費の支払い
- 積立資金の支払い

生活資金口座以外の現金・預金が登録されている場合、その残高は総資産に含めますが、生活資金口座へ自動的には移しません。

MVPでは、取得原価、売却益、税金、税引後使用可能額および引出可能年月を扱いません。

## 月次計算順序

各月は、次の順序で計算します。

1. 前月末残高を当月の月初残高として引き継ぐ
2. 当月の定期収入をインフレ調整し、生活資金口座へ入金する
3. 当月の予定売却を実行し、実売却額を生活資金口座へ入金する
4. インフレ調整した当月の基本生活費を生活資金口座から差し引く
5. 当月の積立額を生活資金口座から差し引く
6. 当月の運用対象残高を求め、運用損益を反映する
7. 当月の積立額を積立先の運用資産へ加える
8. 生活資金口座と各運用資産の月末残高を確定する
9. 総資産を計算し、現金不足と資産枯渇を判定する
10. 月末残高を翌月へ引き継ぐ

予定売却の実売却額は、同じ月の生活費と積立に使用できます。

生活資金口座が不足しても積立額は自動調整せず、予定どおり実行します。生活資金口座のマイナス残高は0円へ補正しません。

## インフレ

退職前後の定期収入と基本生活費は、シミュレーション開始時点の現在価値で入力します。

年間インフレ率は、次の式で月次インフレ率へ複利換算します。

```text
月次インフレ率 = (1 + 年間インフレ率)^(1/12) - 1
```

対象月の金額は、次の式で求めます。

```text
対象月の金額 =
    入力金額
    × (1 + 月次インフレ率)^開始月からの経過月数
```

将来開始する定期収入や退職後の基本生活費も、シミュレーション開始月から対象月までインフレ調整します。ただし、適用される年月になるまで実際の収入または支出としては計上しません。

シミュレーション開始月の経過月数は0とし、入力金額をそのまま使用します。翌月の経過月数を1とします。

MVPでは収入税を計算せず、インフレ調整後の定期収入をそのまま生活資金口座へ入金します。

## 運用損益

運用資産ごとの年間想定利回りは、次の式で月次利回りへ複利換算します。

```text
月次利回り = (1 + 年間想定利回り)^(1/12) - 1
```

当月の積立額は当月の運用対象に含めず、翌月から運用対象にします。当月に売却した金額は、当月の運用対象から除外します。

各運用資産の月末残高は、次の式で求めます。

```text
当月運用対象残高 =
    max(月初残高 - 当月実売却額, 0)

当月運用損益 =
    当月運用対象残高 × 月次利回り

月末残高 =
    月初残高
    + 当月積立額
    - 当月実売却額
    + 当月運用損益
```

この規則により、当月の積立額と当月の実売却額には当月の運用損益を付けません。

## 売却

売却予定は、指定された月に運用資産から生活資金口座へ資金を移す処理として扱います。

売却予定額が売却時点の運用資産残高を超える場合、実売却額は資産残高を上限とします。

```text
実売却額 = min(売却予定額, 売却時点の資産残高)
売却できなかった額 = 売却予定額 - 実売却額
```

実売却額だけ運用資産の残高を減らし、同額を生活資金口座へ入金します。運用資産の残高はマイナスにしません。

売却予定額の全額を実行できなかった場合も、残額を翌月以降へ自動延期しません。売却できなかった事実を結果へ表示するかは、対象User Storyで決定します。

生活資金口座が不足しても、運用資産を自動売却しません。

同じ月または同じ運用資産に複数の売却予定がある場合の集約方法は未決定です。決定前に、実行順序へ依存する計算を実装しません。

## 総資産

総資産は、月末時点のすべての保有資産の残高を合計して求めます。

```text
総資産 =
    生活資金口座の月末残高
    + 生活資金口座以外の現金・預金の月末残高の合計
    + すべての運用資産の月末残高の合計
```

生活資金口座がマイナスの場合は、そのマイナス残高も総資産へ反映します。

MVPでは、保有資産を仮想売却して税金を差し引く計算や、税引後使用可能額の計算を行いません。

## 現金不足と資産枯渇

現金不足と資産枯渇は、別の状態として月末に判定します。

### 現金不足

生活資金口座の月末残高が0円未満の場合、現金不足と判定します。

マイナス残高は0円に補正せず、累積して賄えなかった生活資金として翌月へ引き継ぎます。後の定期収入や予定売却によって、マイナス残高が解消される場合があります。

シミュレーション期間内で最初に現金不足が発生した年月を記録します。MVPでは、後に現金不足が解消した年月などの回復履歴は記録しません。

### 資産枯渇

月末の総資産が0円以下の場合、資産枯渇と判定します。

現金不足が発生していても、総資産が0円を超えている場合は資産枯渇とは判定しません。

資産枯渇後も終了年齢に達する月までシミュレーションを継続し、最初に資産枯渇が発生した年月を記録します。シミュレーション期間中に一度でも資産枯渇が発生したプランは、後に総資産がプラスへ回復しても「終了年齢まで総資産を維持できた」とは判定しません。

MVPでは、資産枯渇後に総資産が回復した年月などの回復履歴は記録しません。

## MVPで扱わない計算

MVPでは、以下の計算を行いません。

- 月内の日付による日割り計算
- 日次または確率的な運用シミュレーション
- 収入、売却または取崩しに対する税計算
- 取得原価、売却益および売却後取得原価の計算
- 税引後使用可能額の計算
- 引出可能年月による売却制限
- 現金不足時の自動売却
- 現金不足時の積立額の自動調整
- 実行できなかった売却予定の自動延期

## 未決定事項

以下は、影響するUser StoryのAcceptance Criteriaを確定するまでに追加で決定します。

- 金額計算の端数処理
- 不正または矛盾する入力値の検証方法
- 退職前後の定期収入をそれぞれ一件に限定するか
- 複数の積立・売却予定を登録できるか
- 同じ月または同じ資産に複数の予定がある場合の集約方法
- 結果を名目額だけで表示するか、現在価値も併記するか
- 売却予定額を全額売却できなかった事実を表示するか

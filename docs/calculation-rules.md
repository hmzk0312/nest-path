# MVP計算ルール

この文書は、NestPathのMVPにおける月単位のシミュレーション規則を定義します。

READMEに記載されたMVP要求を補足し、同じ入力から常に同じ計算結果を得るために、月内の処理順序、運用損益、税金、現金不足および資産枯渇の判定方法を明確にします。

この文書は要求と計算上の振る舞いを扱います。アーキテクチャ、技術構成および内部データモデルは定義しません。

## 期間と年月の扱い

- シミュレーションは月単位で行います。
- 入力した現在残高は、シミュレーション開始年月の月初残高として扱います。
- 生年月を必須入力とし、年齢は生年月と対象年月から算出します。
- 退職年月は最後の勤務月とします。退職前給与と退職前生活費は退職年月まで、退職後生活費はその翌月から適用します。
- 収入や積立の開始年月と終了年月は、どちらの月も対象期間に含めます。
- シミュレーション終了年齢に達する月を最終月とし、その月の月末残高まで計算します。

## 生活資金口座

現金・預金として登録した資産のうち、一つを生活資金口座として指定します。

生活資金口座には、以下の入出金を反映します。

- 税引後収入の入金
- 税引後の売却・取崩し代金の入金
- 生活費の支払い
- 積立資金の支払い

その他の現金・預金は、総資産および引出可能な場合の税引後使用可能額に含めますが、生活資金口座へ自動的には移しません。

その他の現金・預金から生活資金口座へ資金を移す場合は、予定取崩しとして明示的に設定します。

## 月次計算順序

各月は、次の順序で計算します。

1. 前月末残高を当月の月初残高として引き継ぐ
2. 当月から引出可能になる資産を反映する
3. 当月の収入をインフレ調整し、概算税率を差し引いて生活資金口座へ入金する
4. 当月の予定売却・取崩しを実行し、税引後受取額を生活資金口座へ入金する
5. インフレ調整した生活費を生活資金口座から差し引く
6. 当月の積立額を生活資金口座から差し引く
7. 当月の運用対象残高を求め、運用損益を反映する
8. 当月の積立額を積立先資産の残高と取得原価へ加える
9. 各資産の月末残高と取得原価を確定する
10. 総資産、税引後使用可能額および現金残高を計算する
11. 現金不足、資産枯渇、売却未実行などを判定して記録する
12. 月末残高を翌月へ引き継ぐ

予定売却の税引後代金は、同じ月の生活費と積立に使用できます。

生活資金口座が不足しても積立額は自動調整せず、予定どおり実行します。

## インフレと収入税

生活費、給与、年金および退職後の労働収入は、シミュレーション開始時点の現在価値で入力します。

年間インフレ率は、次の式で月次インフレ率へ複利換算します。

```text
月次インフレ率 = (1 + 年間インフレ率)^(1/12) - 1
```

対象月の金額は、次の式で求めます。

```text
対象月の金額 =
    入力金額
    × (1 + 月次インフレ率)^開始月からの経過月数
```

将来開始する収入や退職後生活費も、シミュレーション開始月から対象月までインフレ調整します。ただし、設定された開始年月になるまで実際の収入または支出としては計上しません。

シミュレーション開始月の経過月数は0とし、入力金額をそのまま使用します。翌月の経過月数を1とします。

収入はインフレ調整後の額面金額に、その収入へ設定された概算税率を適用します。

```text
税引後収入 =
    インフレ調整後の額面収入
    × (1 - 概算税率)
```

## 運用損益

年間想定利回りは、次の式で月次利回りへ複利換算します。

```text
月次利回り = (1 + 年間想定利回り)^(1/12) - 1
```

当月の入金は当月の運用対象に含めず、翌月から運用対象にします。当月に資産から出た金額は、当月の運用対象から除外します。

```text
当月運用対象残高 =
    max(月初残高 - 当月出金額, 0)

当月運用損益 =
    当月運用対象残高 × 月次利回り

月末残高 =
    月初残高
    + 当月入金額
    - 当月出金額
    + 当月運用損益
```

この規則により、次のように扱います。

- 当月の積立額には当月の運用損益を付けない
- 当月の売却額には当月の運用損益を付けない
- 生活資金口座への当月収入と売却代金には、当月の運用損益を付けない
- 生活資金口座から支出・積立に使用した金額には、当月の運用損益を付けない

## 売却と取崩し

資産は、設定された引出可能年月の月初から売却または取崩しが可能になります。

引出可能年月より前に予定された売却・取崩しは、次のように扱います。

- 売却・取崩しを実行しない
- 生活資金口座へ入金しない
- 引出可能時期前であることを警告する
- 翌月以降へ自動的に延期しない
- シミュレーションは継続する

売却予定額が売却時点の資産残高を超える場合、実際の売却額は資産残高を上限とします。

```text
実売却額 = min(売却予定額, 売却前残高)
売却不足額 = 売却予定額 - 実売却額
```

売却不足が発生した場合は警告を記録し、実際に売却できた金額だけを税計算と生活資金口座への入金に使用します。資産残高はマイナスにしません。

同じ資産に同じ月の売却予定が複数ある場合は、予定額を合計してから残高上限を適用します。

資産は、現金不足を理由として自動売却しません。

## 取得原価と売却益

MVPでは保有口数や個々の購入単価を管理せず、取得原価を商品全体の取得原価として扱います。

一部売却時は、売却前残高に対する実売却額の割合で取得原価を按分します。

```text
売却割合 =
    実売却額 ÷ 売却前残高

売却分の取得原価 =
    売却前取得原価 × 売却割合

売却益 =
    実売却額 - 売却分の取得原価

売却後残高 =
    売却前残高 - 実売却額

売却後取得原価 =
    売却前取得原価 - 売却分の取得原価
```

全額売却した場合は、端数を残さず、残高と取得原価をともに0円にします。

積立時は、積立額を残高と取得原価の両方へ加えます。

```text
積立後残高 =
    積立前残高 + 積立額

積立後取得原価 =
    積立前取得原価 + 積立額
```

## 売却・取崩し時の概算税

### 課税口座および自社株・持株会

課税口座および自社株・持株会には、シミュレーションで共通の売却益概算税率を適用します。

```text
課税対象売却益 =
    max(売却益, 0)

概算税額 =
    課税対象売却益 × 売却益概算税率

生活資金口座への入金額 =
    実売却額 - 概算税額
```

売却損には課税しません。異なる商品、月または年度との損益通算や、損失の繰越控除は行いません。

### NISA

NISAの売却益には課税せず、実売却額の全額を生活資金口座へ入金します。

### DC・iDeCo

DC・iDeCoには商品ごとの概算受取税率を設定します。

```text
税引後受取額 =
    実取崩し額 × (1 - 概算受取税率)
```

受取方法、各種控除、加入年数などに基づく税額の自動計算は行いません。

### 現金・預金

現金・預金の取崩しには課税せず、実取崩し額の全額を生活資金口座へ入金します。

## 総資産と税引後使用可能額

総資産は、引出可能時期にかかわらず、すべての資産残高を合計して求めます。生活資金口座がマイナスの場合は、そのマイナス残高も総資産から差し引きます。

税引後使用可能額は、月末時点で引出可能な資産をすべて換金したと仮定した税引後金額です。

```text
税引後使用可能額 =
    生活資金口座残高
    + 生活資金口座以外の引出可能な現金・預金
    + 引出可能なNISAの残高
    + 引出可能な課税資産の税引後換金額
    + 引出可能なDC・iDeCoの税引後受取額
```

生活資金口座以外の課税資産は、次の式で税引後換金額を求めます。

```text
含み益 =
    max(月末残高 - 月末取得原価, 0)

仮想売却税額 =
    含み益 × 売却益概算税率

税引後換金額 =
    月末残高 - 仮想売却税額
```

DC・iDeCoは、次の式で税引後受取額を求めます。

```text
税引後受取額 =
    月末残高 × (1 - 概算受取税率)
```

引出可能時期より前の資産は、総資産には含めますが、税引後使用可能額には含めません。

税引後使用可能額を求めるための換金計算は判定用の仮想計算です。実際の売却、取得原価の減少、生活資金口座への入金、および翌月以降の残高変更は発生させません。

## 現金不足と資産枯渇

現金不足と資産枯渇は、別の状態として月末に判定します。

### 現金不足

生活資金口座の月末残高が0円未満の場合、現金不足と判定します。

マイナス残高は0円に補正せず、累積して賄えなかった生活資金として翌月へ引き継ぎます。後の収入や予定売却によって、マイナス残高が解消される場合があります。

現金不足が発生した場合、少なくとも以下を記録します。

- 最初に現金不足が発生した年月
- 月末の現金残高
- 不足額
- その時点の総資産
- その時点で売却可能な資産
- 後に現金不足が解消した年月

現金不足が後に解消されても、途中で発生した履歴は残します。

### 資産枯渇

月末の税引後使用可能額が0円以下の場合、資産枯渇と判定します。

資産枯渇後もシミュレーションは継続します。後の収入などによって税引後使用可能額がプラスへ回復した場合は、その推移も記録します。

ただし、シミュレーション期間中に一度でも資産枯渇が発生した計画は、「終了年齢まで資産を維持できた」とは判定しません。

現金不足が発生していても、税引後使用可能額が0円を超えている場合は、資産枯渇とは判定しません。

資産枯渇が発生した場合、少なくとも以下を記録します。

- 最初に資産枯渇が発生した年月
- 月末の税引後使用可能額
- その時点の総資産
- 後に税引後使用可能額がプラスへ回復した年月

資産枯渇が後に解消されても、途中で発生した履歴は残します。

## MVPで扱わない計算

MVPでは、以下の計算を行いません。

- 月内の日付による日割り計算
- 日次または確率的な運用シミュレーション
- 日本の税制に基づく税額の自動計算
- 所得控除や社会保険料の詳細計算
- 住民税の年度差
- 課税口座の商品間・月間・年度内の損益通算
- 売却損の繰越控除
- 退職所得控除の詳細計算
- DC・iDeCoの受取方法や加入年数に基づく詳細な税計算
- 現金不足時の自動売却
- 現金不足時の積立額の自動調整
- 売却できなかった予定の自動延期

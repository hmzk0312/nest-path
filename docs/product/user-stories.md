# NestPath User Stories

## この文書について

この文書は、NestPathの現在のMVPで実現するUser Storyと、各User Storyの責務、状態、依存関係を管理するための正本です。

各User Storyの詳細な仕様、具体例、受け入れ条件、単体テスト観点、完了条件は、Issue化するときにGitHub Issueへ記載します。この文書には、MVP全体を見渡すために必要な情報を記載し、個別Issueの詳細を重複して管理しません。

### 文書の状態

- 状態: Proposed
- 最終更新日: 2026-09-28
- 対象: 縮小版MVP
- 追跡するUser Story数: 18件
- MVP対象: 12件
- 他のUser Storyへ統合: 2件
- MVP後へ延期: 4件

### User Storyの状態

- MVP
  - 現在のMVPで実現する
- 統合
  - 責務を別のUser Storyへ移し、元の番号は追跡用に維持する
- MVP後
  - 現在のMVPでは実現せず、将来候補として維持する

既存のUser Story番号は削除または再利用しません。

### 管理方針

- User Storyは、利用者またはMVPにとっての価値を表す要求単位とする
- 一度に実装・テスト・レビューするには大きいUser Storyは、親User Storyを維持したままTaskへ分割する
- 詳細仕様はGitHub Issueを正とし、この文書には要約と対応関係を記録する
- 未決定事項をUser Story作成時に先回りして決定しない
- 将来の可能性だけを理由に、MVPの範囲や実装を複雑化しない
- MVP後の候補と、現在のプロダクト方針として扱わない機能を区別する
- 実装から得た知見によって変更が必要になった場合は、この文書と関連Issueの両方を見直す

## MVPの目的

NestPathの現在のMVPは、現在の資産と今後の収支を前提に、利用者が次の問いを検討できるようにすることを目的とします。

> この退職計画で、設定した年齢まで生活資金が持つか。

MVPでは一つのプランを計算します。

利用者は入力条件を変更して再計算することで、退職年月、積立、売却などの条件を検討します。

二つのプランを同時に比較する機能はMVP後の候補とします。

## MVP全体の受け入れ条件

- 生年月、シミュレーション開始年月、退職年月、終了年齢を設定できる
- 一つの生活資金口座と、一つ以上の運用資産を設定できる
- 退職前後の定期収入と基本生活費を設定できる
- 運用資産への積立予定を設定できる
- 運用資産から生活資金口座への売却予定を設定できる
- 年間想定利回りと年間インフレ率を設定できる
- 開始年月から終了年齢に達する月まで、一つのプランを月単位で計算できる
- 月ごとの生活資金口座残高と総資産を確認できる
- 最初に生活資金口座が不足する年月を確認できる
- 終了年齢まで総資産を維持できたか確認できる
- 入力条件を変更して再計算できる

## 共通方針

- シミュレーションは月単位で行う
- 退職条件は退職年月を正とし、退職年齢は生年月と退職年月から導出する
- 退職年月を最後の勤務月とし、その翌月から退職後として扱う
- MVPでは一つのプランだけを扱う
- 資産区分は、現金・預金と運用資産に限定する
- 現金・預金の一つを生活資金口座とする
- 取得原価、売却益、税金、税引後使用可能額を扱わない
- 引出可能年月を扱わない
- 売却額は運用資産から差し引き、同額を生活資金口座へ入金する
- 予定売却額が残高を超える場合、実売却額を残高までに制限する
- 資産残高をマイナスにしない
- 現金不足を理由とした資産の自動売却は行わない
- 実行できなかった売却予定を翌月へ自動延期しない
- 生活資金口座のマイナス残高を0円へ補正しない
- 当月の積立額は、当月の運用対象に含めない
- 当月の売却額は、当月の運用対象から除外する
- 運用結果は、一定の想定利回りによる単一の見通しとする
- 確率的な市場変動は計算しない
- MVPでは入力内容を永続化しない
- 実際の個人データはGitで管理しない
- サンプルとテストには架空のデータを使用する

# E2 計算ロジック

## US-04 年率とインフレを月次計算する

### 状態

MVP。現行US-04から税引後収入計算を除外する。

### 目的

年間インフレ率と年間想定利回りを、月次シミュレーションで使用できる値へ変換する。

### 受け入れ条件の概要

- 年間インフレ率を複利で月次換算できる
- 年間想定利回りを複利で月次換算できる
- 開始月の経過月数を0として金額をインフレ調整できる
- 退職前後の収入と生活費を、シミュレーション開始月を基準に調整できる
- 収入税を計算しない

### 依存関係

US-01。

## US-05 単一資産の月次運用損益を計算する

### 状態

MVP。

### 目的

運用資産の月次推移に使用する最小計算単位を確立する。

### 受け入れ条件の概要

- 当月運用対象残高を求められる
- 当月入金を当月の運用対象に含めない
- 当月出金を当月の運用対象から除外する
- 月初残高、入金、出金、運用損益から月末残高を求められる
- 一定利回りによる単一の見通しとして計算する

### 依存関係

US-04。

## US-08 総資産を計算する

### 状態

MVP。税引後使用可能額の計算は除外する。

### 目的

生活資金口座と運用資産の合計から、月末時点の総資産を求める。

### 受け入れ条件の概要

- すべての資産残高を総資産へ含める
- 生活資金口座のマイナス残高を総資産へ反映する
- 税引後使用可能額を計算しない
- 仮想売却や仮想税計算を行わない

### 依存関係

US-02。

## US-09 現金不足と資産枯渇を判定する

### 状態

MVP。税引後使用可能額による判定は除外する。

### 目的

生活資金口座の不足と、総資産全体の枯渇を区別する。

### 受け入れ条件の概要

- 生活資金口座が0円未満なら現金不足と判定できる
- 総資産が0円以下なら資産枯渇と判定できる
- 現金不足でも総資産がプラスなら資産枯渇としない
- 生活資金口座のマイナス残高を0円へ補正しない
- 一度でも資産枯渇したプランを、終了年齢まで維持できなかったと判定できる

### 依存関係

US-08。

# E3 シミュレーション統合

## US-10 当月の売却予定を実行する

### 状態

MVP。US-06の実売却額制限を統合する。

### 目的

当月の予定売却を実行し、運用資産から生活資金口座へ資金を移す。

### 受け入れ条件の概要

- 当月分の売却予定だけを対象にできる
- 実売却額を売却時点の資産残高以下に制限できる
- 実売却額だけ運用資産の残高を減らせる
- 実売却額と同額を生活資金口座へ入金できる
- 運用資産の残高をマイナスにしない
- 実行できなかった予定を翌月へ自動延期しない
- 税金、取得原価、売却益を計算しない
- 引出可能年月による実行制限を行わない

### 依存関係

US-01、US-02、US-03。

## US-11 一か月のシミュレーションを実行する

### 状態

MVP。

### 目的

一か月の収入、売却、生活費、積立、運用、判定を、定められた順序で実行する。

### 受け入れ条件の概要

- 退職前後に対応する定期収入を生活資金口座へ入金できる
- 当月の売却予定を実行できる
- 退職前後に対応する基本生活費を生活資金口座から差し引ける
- 当月の積立額を生活資金口座から差し引ける
- 当月の積立額を当月の運用対象に含めない
- 当月の売却額を当月の運用対象から除外できる
- 月末に積立額を積立先資産へ反映できる
- 月末の生活資金口座残高と各運用資産残高を確定できる
- 総資産を計算できる
- 現金不足と資産枯渇を判定できる
- 一か月分の結果を返せる

### 月次処理順序

1. 当月の定期収入を生活資金口座へ入金する
2. 当月の予定売却を実行する
3. 当月の基本生活費を生活資金口座から差し引く
4. 当月の積立額を生活資金口座から差し引く
5. 当月の出金を除いた運用対象残高へ運用損益を反映する
6. 当月の積立額を積立先資産へ加える
7. 月末残高と総資産を確定する
8. 現金不足と資産枯渇を判定する

### 依存関係

US-03、US-04、US-05、US-08、US-09、US-10。

## US-12 終了年齢までシミュレーションする

### 状態

MVP。詳細な回復履歴は除外する。

### 目的

開始年月から終了年齢に達する月まで月次処理を反復し、資産推移と最初の不足・枯渇を得る。

### 受け入れ条件の概要

- 月末残高を翌月の月初残高として引き継げる
- 生活資金口座のマイナス残高をそのまま引き継げる
- 開始年月から終了年月まで各月を一度ずつ計算できる
- 各月の生活資金口座残高と総資産を保持できる
- 最初の現金不足年月を記録できる
- 最初の資産枯渇年月を記録できる
- 資産枯渇後も終了年月まで計算を継続できる
- 終了年齢まで総資産を維持できたか判定できる
- 不足または枯渇からの回復履歴は記録しない

### 依存関係

US-01、US-09、US-11。
